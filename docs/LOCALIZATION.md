# 商品本地化与跨市场上架

本地入口：`http://127.0.0.1:3100/tools/localization`。使用现有中台账号登录，`pnpm dev` 启动前端与团队网关。完整工具及仿真机器接入尚未整体部署、未推送。2026-11-13经用户授权，已单独部署限定mock商品的未上架保存通道，在Home Monitor_PH创建完整双规格4SKU测试商品50821595037，3张展示图、规格配图、图文详情、7项属性、独立SKU价格库存和包装物流均回读匹配，状态UNLIST，未执行发布；早先单SKU测试44671691020保留。

## 操作流程

1. 仿真平台调用 `GET /api/v1/localization/integration/shops`，按授权店铺选择目标店铺和文案语言，再调用 `POST /api/v1/localization/integration/imports` 提交来源商品与目标信息。正式字段、类型和示例见 [仿真接入 API 文档](LOCALIZATION-INTEGRATION.md)。
2. 中台持久化接收记录、来源快照和独立市场草稿，并自动生成目标语言文案。页面上方“仿真接收记录”显示生成状态；完成后打开对应草稿审核。失败时保留草稿，可从记录中重新生成。
3. 核对或编辑标题、卖点、描述、规格名称及规格值。选择目标市场类目、品牌、属性和物流，填写各 SKU 最终售价、库存、重量及尺寸。来源类目和属性 ID 不会沿用；汇率不能代替最终售价。
4. 接入已完成的 Listing 图片或上传图片，保存后完成市场与图片核对。预览显示来源原文与目标文案、目标店铺、图片、规格、售价及物流；图片中文字不会随文案翻译。
5. 运营核对无误后主动点击发布。任务结果、远端 ID 和失败阶段会持久化；超时不明确先核对远端，失败后保留草稿供修正与恢复。

商品来源仅通过仿真平台接入 API POST；本地化工具不提供手动 JSON 导入入口。仿真接入与浏览器草稿 API 是两组不同用途的接口，页面通过仿真接收记录打开对应草稿。

## 数据与安全

本工具新增文件采用 `localization` 命名。数据默认保存于项目根目录 `.local/localization`，可用服务端 `LOCALIZATION_DATA_DIR` 调整；按账号隔离，文件权限 0600，目录权限 0700，已被 Git 的 `.local/` 规则排除。来源、草稿、任务、图片及中央创建回执分开保存。保留此目录才能恢复历史任务；不要当缓存清理。当前本地网关按单实例运行。

Shopee 凭据仍由现有中央授权服务保存和续期；浏览器仅持有现有中台 HttpOnly 会话。AI 配置由 Listing 的加密配置只读适配，不复制个人项目密钥，不返回密钥。Listing 核心文件、原型与个人选品项目未修改。

远程图片下载固定经过校验的公网 DNS 地址，拒绝内网、特殊地址、重定向及超限图片；本地图片资源校验登录账号归属。资源读取不是公开图床。

## 发布与恢复

发布路径由服务端核查店铺类型。当前实现普通 `product` 路径：上传图片 → 以 `UNLIST` 创建 → 初始化并核对规格 → 确认上架结果。只有本工具记录的远端商品才能执行后续步骤，不更新既有在售商品。逐项检查上架结果，不能只看 HTTP 成功。

`global_product` 需要现有授权链路未提供的 merchant 凭据；跨境或类型不明确的店铺会显示具体原因并阻止创建。**本版没有实现可用的全球商品发布链路，不能宣称所有跨境店铺均已支持。** 后续须先核对实际店铺 CNSC 资格及授权能力，再增加商家维度适配；不会用 shop token 冒充 merchant token。

每份草稿使用独立持久任务与远端 SKU 标记。重复点击复用任务，中央创建还使用独占锁和持久回执。上传过程中逐张保存进度；同图恢复复用已上传结果，换图后重新上传。

| 状态 | 含义与操作 |
| --- | --- |
| 准备发布 / 创建中 | 等待后台处理，刷新结果 |
| 未完成 | 尚未确认创建；修正草稿后继续同一任务 |
| 创建结果待核对 | 超时或响应不明；只查回执或远端 SKU，不盲目再次创建 |
| 商品已创建，后续步骤未完成 | 已保存远端 ID；继续规格与上架，不再创建商品 |
| 发布完成 | 平台创建与后续结果均通过当前适配器校验 |

远端分页查询没有发现商品，不等于已经证明创建未发生；该情况继续保持待核对，不自动重建。服务端创建锁异常遗留时同样需要先对账。不能通过清理任务或创建另一份草稿来绕过结果不明状态。

## 页面与恢复接口

运营页面使用受中台登录保护的 `/api/v1/localization` 查询来源商品、草稿、店铺和发布任务，并保存编辑后的草稿。商品接入只使用上方所述仿真 API；不要调用浏览器草稿 API 来模拟仿真平台。草稿与任务可通过列表接口恢复；失败任务可恢复或核对不明确的创建结果。图片上传经认证后返回私有资源地址，每张不超过 8MB。

中央新增受现有 `DevelopmentGuard` 保护的 `/api/v1/development/localization/shops/:id/:operation`，不接受任意 URL、签名或 Token。2026-11-13部署的独立保存通道仅开放capabilities、metadata、upload、create、save_variations、reconcile；限定店铺、指定标题、零库存、最多双规格4SKU mock。complete/publish均返回403，不能作为正式发布入口使用。仿真机器接入与完整工具仍未整体部署。

## 验证边界

模拟测试使用本地 fixture 和测试数据库，涵盖导入、账号权限、市场隔离、草稿修订冲突、刷新/重启恢复、显式确认、幂等、超时对账、图片上传断点及部分创建恢复。不会访问真实商品写入接口。

真实只读核查已确认 Home Monitor_PH（618217104）返回 `CONNECTED`，PH / PHP / English；读取了 2194 个类目、10 个物流渠道及真实售价、库存、标题、描述、图片和规格文字限制。聚合读取初次返回 502，分项排查及后续聚合复核均返回 200；不据此宣称平台长期可用性已验收。AI 设置的脱敏读取确认策划文本模型已配置，但未触发实际付费调用；真实发布、实际 AI 文案质量及模型收费调用尚未验证。Shopee 官方文档页面访问返回 403，本次受控PH商品已完成真实规格初始化、详情及配图保存回读；其他市场仍需独立联调。真实发布仅限用户随后明确确认的测试商品。

## 从 FastMoss 市场调研创建草稿

在中台的「市场调研」上传马来西亚 TikTok 销量榜 XLSX，核对预览后标注日、周或月。日期对应导出时在 FastMoss 选择的统计周期。点击「一键跟卖」并选择已连接的 Shopee 店铺，可进入本地化草稿。榜单原价和原图在草稿中供参考，最终售价、真实规格、库存及上架图片由运营填写。

选品评分与跟卖文案使用「AI 设置」里的文本策划模型。未配置时仍可导入、筛选和编辑跟卖草稿。同一账号、TikTok 商品和店铺重复跟卖时打开原草稿。榜单、评分和草稿来源随 `LOCALIZATION_DATA_DIR` 下的 `selection/` 持久保存。

线上构建本地化 API 和审核前端后，使用本地化 Nginx 片段将 `/tools/selection` 转发到审核前端。`/api/v1/localization/selection/` 复用现有本地化 API 路由。更新审核前端时一并更新其静态资源覆盖目录。主控制台升级到包含「市场调研」菜单的构建后，可从主菜单直接进入。
