业务流程：接收仿真商品 → 选择已授权目标店铺 → 本地化文案和目标市场商品适配 → 预览、人工确认 → 一键发布 → 跟踪结果；同一来源商品可继续生成其他市场的独立版本。首版每次发布一个目标店铺。

## 必须交付

1. 约定带版本号的仿真商品导入结构：来源系统、唯一商品标识、名称、描述、图片、真实参数、SKU/规格、重量尺寸等；保留源快照；先提供 JSON 导入/接口和示例，不虚构已有仿真连接。图片输入不能用任意 URL 访问内网。
2. 来源商品与市场草稿分开：一个源商品、多份目标店铺版本；修改一份不影响其他版本。草稿服务端持久化，刷新恢复。
3. 从现有中央授权服务读取可用店铺；国家、币种由店铺确定，语言默认当地语言且可选。不能复制 Shopee 密钥到浏览器或 Git。
4. 本地化标题、卖点、描述、规格名；允许修改；保留真实参数，禁止补造功效、材质、认证等。复用现有 AI 配置服务的安全密钥访问方式，不能让图片专用模型承担文本翻译；如现有策划模型适用可复用，不复制配置。
5. 查询目标市场类目/属性/品牌、物流和可用发布限制，显示候选、允许运营确认；不能复制其他市场 ID。规格、售价、库存、重量尺寸、物流等发布必填信息要完整校验。汇率辅助不等于最终售价。
6. 可选择 Listing 已完成图片；当前图片文件在各运行环境本地，不保证跨电脑共享，需设计受认证资源读取/上传途径。图片内文字不因文案翻译而自动改变，预览中提示核对。
7. 发布前完整预览；目标店铺明确，运营主动点击才写入。使用真实适用的 product / global_product 路径；店铺资格、权限不符合要说明。不能把读取成功当写入成功。
8. 发布为持久任务，幂等、防双击重复创建；保存远端商品 ID、阶段、错误及时间；多规格/媒体上传失败可恢复。请求超时结果不明确时先查远端，不能盲目重试 add_item。区分「已创建，后续步骤未完成」与「未创建」。
9. 结果成功/失败可追踪，失败保留草稿，可修正后重试。上传、计划、任务状态不会因刷新浏览器消失。
